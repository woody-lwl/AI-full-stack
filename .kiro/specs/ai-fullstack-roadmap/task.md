# Implementation Plan: AI 全栈学习路线

## Overview

### 定位与执行规则

本计划是**写作与学习任务清单**，不是软件功能实现计划。每个章节任务都要形成“按需生成教程 → 运行示例 → 完成真实场景练习 → 对照验收 → 更新 NOTES”的闭环；仅阅读或仅生成 Markdown 不算完成。

- Kiro 一次只按需生成一章；当前章的代码、练习和验收未完成前，不囤积后续教程。
- 章节正文统一使用 `design.md` 第 4 节模板：目录、场景引入、可运行代码示例、设计思考、常见坑、最佳实践、练习题、小结与自检。
- 未来章节的 Markdown stem 必须与 `code/` 下章级目录名一致：`{NN}-{chapter-slug}.md` ↔ `code/{NN}-{chapter-slug}/`；一章有多个独立示例时，只在章目录内使用 `{NN}-{example-slug}/` 编号子目录。
- Python 示例以 Python 3.12+ 验证，Go 示例以 Go 1.22+ 验证；适用时运行 `pytest` / `go test`。前端及工程化示例按章节给出的非交互命令完成构建或自动化验证。
- 每章完成后，在对应模块的 `NOTES.md` 追加完成日期、学了什么、3~5 条关键要点、遗留疑问以及运行/测试证据，不覆盖历史记录。
- `P0`：近期优先或主线地基；`P1`：中期核心/AI 全栈必备；`P2`：后期进阶或非近期扩展。
- 项目原型可以提前暴露集成问题，但 MVP 不等同于 Requirement 11 正式验收；正式验收不得省略自动化测试、部署、监控、可访问地址或架构取舍说明。

## 学习节奏与里程碑提醒

- **前 1~2 个月（P0）**：推进 Python 基础、测试工程至工具实战，并并行完成“读懂 Go”。里程碑不是读完章节，而是交付一个可用于实际工作的测试工具，并能准确解释项目 Go 代码的输入输出、数据流、并发与错误路径。
- **第 3~4 个月（P1）**：推进设计思维、FastAPI、LLM/RAG、工程化起步，并使用前序准备产物形成项目 A MVP。MVP 只证明核心链路跑通，不代表 Req 11 正式达标。
- **第 5~6 个月（P1）**：推进前端、CI-CD、云部署和监控；先补齐项目 A 正式验收，再进行项目 B 集成与正式验收。
- **6 个月后（P2）**：在 Python 主线模块①~⑥达标后，系统学习 Go 并完成 Go 后端服务。
- **投入假设**：推荐路径每周约 8~12 小时；3 个月加速路径约 18~25 小时，只压缩范围、不降低已声明里程碑的质量标准。
- **进度原则**：里程碑验收优先于日历。阶段结束但验收证据不足时，先补齐失败项，再进入依赖它的正式里程碑。
